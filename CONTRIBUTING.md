# Contributing to release-audit-2026

Thanks for helping with the pre-release audit!

## How to contribute

1. **Open an issue first.** Before making changes, open or comment on an issue so the team can discuss scope. Audit work is tracked as sub-issues under the "Release audit checklist" parent issue.
2. **Create a branch** off `main` with a descriptive name, e.g. `audit-notes` or `risk-review-updates`.
3. **Make your changes**, keeping pull requests focused on a single topic.
4. **Open a pull request** into `main` and keep the branch up to date with the latest `main` to avoid merge surprises.
5. **Get a review** before merging.

## Guidelines

- Keep notes and documentation in Markdown under `docs/`.
- Use clear, descriptive commit messages.
- Link your pull request to the related audit issue(s).
- Report findings honestly, even when the answer is "nothing found".
